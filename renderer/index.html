♣ Regular Update

Endless Treasure (折扣链)

endless_treasure.xlsx — 折扣链数据 / 折扣链推荐 / 折扣链阶段数据 / 折扣链常量. Analysis only for now — no automation wired up yet.

How it fits together

折扣链推荐 (recommendation) is the scheduler: one row per ~2-week window, with a spend-tier formula ([TotalPayment]/[LastWeekPayment]/[LastWeekCount]) that picks one of 3 sibling chain IDs (low/mid/high spender) from 折扣链数据. Only the current window has 开关=TRUE; 节日主题 tags the window with the live event (e.g. "202608dessert"). 折扣链数据 defines each chain's price tier, valid time, and its ordered stage-ID list; 折扣链阶段数据 holds the actual reward content per stage ID. 折扣链常量 holds engine-side unlock thresholds and the currently-valid chain ID allowlist.

Key finding: stage content is generic, not per-event

Every type-2 (event) chain triplet's 固定阶段列表 points at one of only two shared stage-ID templates — Slot A (24801-24824 / 24901-24921 / 25001-25024) or Slot B (25101-25124 / 25201-25221 / 25301-25324) — alternating with every new event window. The actual reward content at matching positions in Slot A and Slot B is identical (verified: e.g. stage 24801 and 25101 both pay "免费金币:200"). So cloning a new event's endless treasure chain does not require creating new 折扣链阶段数据 rows at all — only 3 new 折扣链数据 rows (one per price tier) pointing at whichever slot isn't in use by the still-winding-down previous event, plus one new 折扣链推荐 scheduling row. The two-slot alternation exists purely so a player mid-purchase on the outgoing event's chain doesn't have their stage progression IDs reassigned when the next event's chain goes live.

Chapter Update (新章节)

Rolls the newest PVE chapter forward by one — chest / item / store / notification, asset_ref / icon / pve_chapter, and the map + texture art folders. Chapter numbers are read from pve_chapter.xlsx, not typed.

What this tab does — and what it deliberately doesn't

A chapter number lives in the workbooks in three forms and all three have to move together: the internal map id (88000 → 89000), Chinese numerals in the Alias/PIC columns (七十八 → 七十九), and the plain display number (78 → 79). Every new row is inserted directly after the previous chapter's block rather than appended at the bottom of the sheet, because the game's converters read these ranges positionally.

The five steps below are pure workbook + file work, so they run on the bundled Python with no local install. The remaining chapter steps — Magic Builder (needs pandas/numpy), Screenshots upload (Unity + SVN), Map Builder (Unity scene), Import Config (coder_convert.bat) and Simulation (RunCardEx2) — need Unity, SVN or a full system Python, so they stay in the standalone SkipBo_Chapter_Creator.exe. Run those there, then come back here.

Asset Config refuses to run twice: if the new chapter is already present in pve_chapter.xlsx it stops before touching anything and tells you to svn revert first. A half-applied chapter is worse than none.

♣ Release

Merge Branch Excels → trunk/WorkSpcae3

Row-level 3-way merge. Only the rows your sprint branch changed since it was cut are written into trunk's workbooks, and only where trunk still matches the branch point. Rows, columns and sheets that exist only in trunk are never touched. Always dry-run first.

How the merge decides what to write

Base is the branch at the revision the last merge covered (remembered per branch/trunk pair), or the branch copy point the first time. Each sheet is compared base → branch → trunk by its descriptor Key column. A row the branch added is inserted after the same predecessor row in trunk; a row the branch changed gets only its changed cells written, and only if trunk did not change the same cell; a row the branch deleted is listed but kept unless you tick the option. New workbooks, sheets and columns are copied over; descriptor JSON and PostConvert Lua get a 3-way text merge.

Conflicts are anything a human must decide: add-collision (the branch added a key trunk already has with other content — the "ID must change" case, or trunk already carries a newer version), mod-overlap (both sides edited the same cell), alias-dup (an added row reuses an Alias trunk already has). They are written to conflicts.csv and never applied. Writes go through Excel itself, and every written workbook is re-read afterwards to verify. Nothing is committed to SVN.

Source → Target

Source follows the branch + workspace selected at the top of the window; target defaults to trunk's WorkSpcae3. Both working copies should be committed and updated (svn up) first — the report warns if they are not.

ID remap

One line per ID to rename before merging: xlsx,sheet,old_id,new_id. The key of the branch-added row is renamed and every column whose descriptor Ref points at that sheet is rewritten too. After a dry run, Load collisions fills in the colliding IDs — you type the new ones after the last comma.

Run

Apply unlocks after a dry run with the current settings. It writes through Excel, re-reads every workbook to verify, and never commits — review with svn status / svn diff, run coder_convert, then lock and commit yourself.

        Localization
        
English to Six Languages

        
Paste English strings and get German, Spanish, Dutch, Swedish, French and Danish back. Anything the translator has already approved, or that we already ship, is reused verbatim rather than translated again — only genuinely new text reaches the model.

      


      

        
English Input

        

          
          

        

        

          
          

            
            
            A row can span several lines — Enter adds a line, Ctrl+Enter adds a row. Pasted text stays in one row; use Split lines if it was a list.
          

        

        

          
          

        

        

          
            
            Where each translation comes from
            
          
          

            
Approved — the third-party translator's own corrected text for this exact English string, imported from their delivered workbooks. Reused as-is.

            
Shipped — our existing translation from localization.xlsx or localization_quiz.xlsx. Reused as-is, so the same English never gets two different translations.

            
Generated — new text, translated with the nearest shipped strings and the translator's real corrections in the prompt. Quotation marks are then applied by rule per language (German „…“, French « … », Spanish «…», Dutch ‘…’, Swedish and Danish ”…”), because every single typographic correction the translator made was that same fix.

            
Warnings are advisory and never auto-applied: a dropped placeholder, a string longer than 99% of what we ship in that language, a leftover straight quote, or a translation identical to the English.

Source Event Caches

        
Several steps (convert_layout.lua placement, icon.xlsx/item.xlsx icon references, localization.xlsx rows) cache each source event's data locally so reopening the same event again is instant instead of re-scanning SVN history. This re-checks everything already cached, plus the current latest event of each type, against the live files (free) and SVN (only if not live) — updating each cache only where the data actually changed.
