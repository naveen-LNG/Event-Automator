# Event Ideation Checklist

Purpose: A thinking document for Design to work through before submitting your 1-Pager to PO. This checklist ensures we're proposing events that align with product goals, respect target audience needs, and have clear reasoning.

When to use: During ideation, before you write your 1-Pager. Work through each section and document your thinking—brief notes are fine.

---

## 1. Theme & Audience Fit

Checklist:

- [ ] Theme Name: What is the event theme? (e.g., "Anniversary Hotel", "Beach Vacation")

- [ ] Why This Theme? Write 1-2 sentences on why you chose this theme.
  - Does it resonate with casual card game players?
  - Is it timely (seasonal, holiday, brand moment)?
  - Has this theme been used before?

- [ ] Theme Visual References: Have you added relevant visual references to communicate the theme?
  - Art style: What is the visual style? (e.g., "Elegant, vintage", "Colorful and playful", "Minimalist")
  - Camera angle & perspective: What angle best shows the theme? (e.g., "Top-down", "Isometric", "Side view")
  - Mood board / references: Include images or links to reference art that captures the aesthetic
  - Color palette: What colors define this theme?
  - Do these visual choices match the description and feel appropriate for Skip-Bo?

- [ ] General Audience Impact: Will this theme work for our three player archetypes without harming any?
  - Progression Completionist: Does this offer clear completion/achievement?
  - Casual Escape: Does this avoid time pressure / stay relaxing?
  - Social/Collector: Does this offer cosmetics / customization appeal?
  - Quick assessment: Green / Yellow / Red for each archetype
  - Notes: If any archetype gets Yellow/Red, explain why and if it's acceptable risk.

- [ ] Target Archetype (optional): Are you specifically designing for one archetype? If yes:
  - Which one? Why?
  - How do you ensure the other archetypes don't get adversely affected?

- [ ] Past Performance Reference:
  - What similar events have we run?
  - How did they perform (engagement, revenue)?
  - What worked? What didn't?
  - Is this a refresh of a past theme, or something new?

- [ ] Event Item Visual References: Do all event-related items have visual references attached?
  - Event icon (bottom-center button): Does it capture the theme visually?
  - Event Packs: Visual mockups showing the themed pack design
  - Event rewards cosmetics (card frames, card backs): Design sketches or references
  - Trivia questionnaire (if applicable): Visual style for questions/answers
  - Store additions: Any new items? Visual mockups or descriptions
  - Scene building elements (buildings, decorations): What do they look like? References attached?
  - Other event items: Any other visuals that need reference?
  - Note: All visuals should be cohesive with the overall theme aesthetic.

---

## 2. New Features & Mechanics

For each new feature idea, work through this:

- [ ] Feature Description: What is the new feature/mechanic? (1-2 sentences)

- [ ] Why Add This? Write 1-2 sentences on the intent:
  - What problem does it solve?
  - What player need does it address?
  - How does it improve engagement or monetization?

- [ ] New or Refresh?
  - [ ] New Mechanic: First time we're trying this. (Higher risk.)
  - [ ] Refresh: We've done this before, just new theme/cosmetics. (Lower risk.)

- [ ] Risk Assessment (if new):
  - What could go wrong? (e.g., "Mechanic too complex", "Players don't understand it", "Takes too long to code")
  - Mitigation: How will you mitigate? (e.g., "Detailed tutorial", "Kill-switch in config", "A/B test first")
  - Have we experimented with this mechanic before? (Validation from past events?)

- [ ] Player Feedback Check:
  - Do we know if players want this? (Community feedback, surveys, past requests?)
  - Or is this a designer hypothesis? (If hypothesis, note it as assumption.)

---

## 3. Product Alignment

- [ ] Annual KPI Goals: What are we optimizing for this year?
  - [ ] Engagement (retention, DAU)?
  - [ ] Monetization (ARPU)?
  - [ ] Balanced?

- [ ] This Event's KPI Contribution: How does this event move toward our goals?
  - Engagement:
    - What mechanic/theme will keep players coming back for 14 days?
    - Expected engagement lift vs. baseline event type? (e.g., "+10% vs. avg Merge", "same", "-5%"?)
    - Any retention risk? (e.g., "Might churn Casual players if too grindy")
  - Monetization:
    - What's the monetization hook? (Cosmetics? Event packs? Battle pass?)
    - Expected ARPU impact? (e.g., "+5%", "neutral", "-3%"?)
    - Any risk to LTV? (e.g., "Cosmetics might oversaturate market")

- [ ] Honest Assessment:
  - Is this a strong contributor to our goals, or a "nice-to-have"?
  - If nice-to-have, is scope small enough to fit without crowding priority work?

---

## 4. Brand & Guidelines Compliance

- [ ] Mattel/Skip-Bo Brand:
  - Does this theme align with Skip-Bo's brand? (Casual, family-friendly, nostalgic)
  - Any themes off-limits?
  - Are we referencing Skip-Bo's heritage appropriately?

- [ ] Player Feedback Constraints:
  - Have we heard complaints about this theme type before?
  - Any community requests or "don't do this again" feedback?

- [ ] Game Design Guidelines:
  - Does this violate any studio standards?
  - Example violations: Pay-to-win mechanics, excessive grind, hidden costs, etc.

---

## 5. Effort Estimation (T-Shirt Sizing)

Estimate the effort for each discipline. Use: Easy / Medium / Hard

(This helps PO decide if we can fit this in our 2-week sprint or need to scope-cut early.)

---

| Area 						| Effort 						| Notes |
|--------					|------						|-------|
| Art          				| Easy / Medium / Hard			| New assets? Simple cosmetics? Custom backgrounds? |
| Engineering  				| Easy / Medium / Hard			| New mechanic code? Config changes? Known patterns? |
| Design       				| Easy / Medium / Hard			| How much iteration/spec work? Clear vision or exploratory? |
| Overall Complexity 		| Easy / Medium / Hard			| Combined risk & feasibility |

---

Notes for Overall Complexity:

- Easy: Refresh of past event (new theme, known mechanics). Can execute in normal sprint.
- Medium: One new element or significant cosmetic changes. Needs some extra capacity.
- Hard: New mechanic or major features. Likely needs scope-cut or extended timeline.

---

## 6. Documentation & Reasoning

Before you submit your 1-Pager, ensure you have:

- [ ] Theme: Clear name + brief reasoning (1-2 sentences)
- [ ] New Features: Each feature described + reasoning (1-2 sentences each)
- [ ] Audience Impact: Notes on how archetypes are affected (Green/Yellow/Red)
- [ ] KPI Alignment: How this contributes to annual goals (Engagement? Monetization? Both?)
- [ ] Risk Flags: Any concerns flagged + mitigation plan
- [ ] Effort Sizing: T-shirt estimates for Art/Eng/Design/Overall

Golden Rule: Every feature and theme choice should have reasoning. If you can't explain why, it's not ready for submission.

---

## 7. Final Sanity Check

Before submitting your 1-Pager, ask yourself:

- [ ] Thinking Quality: Have I honestly thought through audience fit, product alignment, and risks? (Not just checking boxes?)
- [ ] Reasoning Documented: Is my reasoning clear enough that PO can quickly understand my thinking?
- [ ] Scope Reality: Are the effort estimates realistic? Can we fit this, or do we need scope-cut?
- [ ] Confidence Level: Am I confident in this proposal? (Green / Yellow / Red)
